# HackAlem AI 2026: что рассказывают 3 649 репозиториев

**Автор:** Dr. Talgar Bayan · **Дата:** 24.09.2026 · **Данные:** публичные GitHub-репозитории организации [BAITC-Hacks](https://github.com/BAITC-Hacks)

> **Дисклеймер.** Все данные взяты из публичных GitHub-репозиториев. Персональные данные участников не анализировались и здесь не публикуются. Это не официальные итоги хакатона. Подробнее: [раздел 7](#7-дисклеймер).

## Кратко

- На хакатон зарегистрировались более 6 000 человек (6 586 заявок), участвовали 2 500. Всего было 12 треков.
- Каждой зарегистрированной команде автоматически создавался репозиторий на GitHub: всего **3 649 репозиториев**.
- **2 395 репозиториев (65,6%) пустые:** в них нет ни одного коммита команды.
- **В 1 057 репозиториях (29,0%)** есть коммиты во время хакатона (13:00–18:00).
- Самым активным стал последний час: **7 867 коммитов с 17:00 до 18:00**. В 18:00 активность резко оборвалась.
- **79%** команд, коммитивших во время хакатона, делали это как минимум в четыре часа из пяти.
- Самый популярный трек: **AI Sana, образование (145 команд)**. Наименее популярный: **Halyk Bank, «Voice Router» (29)**.

## 1. О хакатоне

- **Когда и где:** 23.09.2026, Астана, офлайн. Время на разработку: 13:00–18:00 (5 часов).
- **Участники:** более 6 000 регистраций (6 586 заявок), 2 500 мест, участники из 21 страны.
- **Команды:** до трёх человек, можно участвовать и одному. Использование Codex при разработке было обязательным.
- **Призы:** $1,1 млн в призах и технологических ресурсах. Среди партнёров — OpenAI и NVIDIA.
- **Вход:** были длинные очереди, часть зарегистрированных не смогла попасть внутрь. Это признали и организаторы.
- **Итоги:** экспертная оценка 24–28 сентября, Demo Day 29 сентября, награждение 1 октября.
- **GitHub:** каждой зарегистрированной команде в организации BAITC-Hacks автоматически создавался репозиторий `hack-<id>-<название-команды>`. После 18:00 репозитории были заархивированы (только чтение).

## 2. Репозитории и коммиты

### 2.1. Два из трёх репозиториев остались пустыми

![Сколько из 3 649 репозиториев получили код?](charts/bilingual/01_funnel.png)

В 2 395 из 3 649 репозиториев (65,6%) нет ни одного коммита команды. Хотя бы один коммит есть в 1 254 репозиториях (34,4%). Коммиты во время хакатона (13:00–18:00) есть в 1 057 репозиториях (29,0%). Ещё в 197 репозиториях есть коммиты, но все они сделаны до начала хакатона. Из репозиториев с коммитами во время хакатона 984 (93,1%) удалось отнести к одному из 12 треков.

**Пустой репозиторий не значит «ленивая команда».** На 6 586 заявок было всего 2 500 мест, и часть людей, простояв в очереди, так и не попала внутрь. Некоторые команды, судя по всему, регистрировались несколько раз: 225 названий команд встречаются в нескольких репозиториях. По данным эти причины не различить.

### 2.2. Уровни коммитов

![Сколько коммитов получил каждый репозиторий?](charts/bilingual/02_commit_levels.png)

Среди репозиториев с коммитами чаще всего встречается уровень 21–50 коммитов (364 репозитория). Больше 100 коммитов — в 30 репозиториях. Медиана для репозиториев хотя бы с одним коммитом — 16 коммитов. Учитываются все ветки, автоматически созданный первый коммит не считается.

## 3. Время и ритм работы

### 3.1. Коммиты по времени

![23 сентября: коммиты по времени](charts/bilingual/03_timeline.png)

После 13:00 число коммитов быстро росло, весь день держалось на высоком уровне, а пик пришёлся на последний час: 7 867 коммитов с 17:00 до 18:00, или 28,7% коммитов в ветках main за время хакатона. Самые активные десять минут — 17:40–17:50 (1 495 коммитов). В 18:00 активность резко оборвалась, а 3 201 репозиторий был заархивирован с 18:01 до 18:51.

### 3.2. Насколько ровно работали команды?

![В скольких из 5 часов команды делали коммиты?](charts/bilingual/04_hours_active.png)

Из 1 057 репозиториев с коммитами во время хакатона 470 (44,5%) делали коммиты в каждый из пяти часов, 837 (79,2%) — минимум в четыре часа. В последний час (17:00–18:00) коммитили как минимум 996 репозиториев (94,2%). То есть большинство команд, начавших работу, продолжали её до конца.

## 5. Методика

1. **Репозитории.** Список всех репозиториев организации BAITC-Hacks получен через GitHub REST API: 3 649 репозиториев, все заархивированы (`src/fetch_repos.py`). Данные собраны в ночь на 24.09.2026.
2. **Коммиты.** Число коммитов в ветке main каждого репозитория (`src/fetch_commit_counts.py`) и время коммитов (`src/fetch_commit_timings.py`, не более 300 коммитов на репозиторий) получены через GitHub GraphQL.
3. **README.** 3 644 README загружены через raw.githubusercontent.com (`src/fetch_readmes.py`); в 5 репозиториях README нет.
4. **Таблица по репозиториям.** В `hackalem_repos_analysis.csv` для каждого репозитория есть: коммиты команды (все ветки, без автоматически созданного первого коммита), коммиты с 13:00 до 18:00, число часов с коммитами и метка трека. Таблица собрана отдельно; скрипта, который её создаёт, в этом репозитории пока нет. Мы сверили её с данными API: для 991 из 1 057 активных репозиториев число часов с коммитами точно совпадает с нашим подсчётом по ветке main; для остальных значение в таблице выше, что соответствует коммитам в других ветках.
5. **Исправления.** Метки треков сверены с текстами README по ключевым словам, расхождения прочитаны вручную, 7 ошибочных меток исправлено (`CASE_FIXES`). В 16 тестовых репозиториях, созданных в июне–июле, автоматический первый коммит сделан другим аккаунтом организаторов, поэтому таблица считала его коммитом команды; мы проверили их на GitHub и исправили (`TEMPLATE_COUNTED_AS_TEAM`). Оба исправления находятся в `src/plot_bilingual_charts.py`.
6. **Проверка.** Все числа на графиках пересчитаны отдельным кодом и совпали. Выборка из 25 репозиториев сверена с GitHub: число репозиториев, статус архива и число коммитов в ветке main совпадают.
7. **Время.** Всё время указано по Астане (UTC+5).
8. **Числа.** Все числа на графиках и в этом README считает `src/plot_bilingual_charts.py` и записывает в `charts/bilingual/facts.json`.

## 6. Ограничения

- Один репозиторий — одна регистрация (команда), а не один человек. В команде было до трёх человек, поэтому число людей по этим данным определить нельзя.
- Данные не объясняют, почему репозиторий пустой: команда могла не прийти, не попасть внутрь, зарегистрироваться повторно или писать код в другом месте.
- Число коммитов не измеряет ни качество, ни объём работы.
- Метки треков для 19 репозиториев, где README остался автоматическим шаблоном, не проверялись.
- График по времени построен только по веткам main; в двух репозиториях больше 300 коммитов, и излишек на график не попал.

## 7. Дисклеймер

- Все данные взяты из **публичных** GitHub-репозиториев организации BAITC-Hacks. Доступа к закрытым системам не было.
- Персональные данные участников (имена, email, телефоны, авторы коммитов) не анализировались и в этом репозитории **не публикуются**. Здесь только агрегированные числа, графики и код; собранные сырые данные (`data/`) не публикуются.
- Это личный анализ автора, **а не официальные итоги** хакатона. Победителей определяет жюри.

## 8. Как воспроизвести

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # GITHUB_TOKEN=...
cd src
python fetch_repos.py             # data/repos.csv
python fetch_commit_counts.py     # data/commit_counts.csv
python fetch_commit_timings.py    # data/commit_timestamps.csv
python fetch_readmes.py           # data/readmes/
python plot_bilingual_charts.py   # charts/bilingual/*.png + facts.json
```

Папки `data/` в репозитории нет, поэтому данные нужно заново собрать из публичных репозиториев скриптами выше. Для последнего шага также нужна таблица `hackalem_repos_analysis.csv` (см. раздел 5, пункт 4). Для графиков нужен шрифт с казахскими буквами (Noto Sans или DejaVu Sans).
