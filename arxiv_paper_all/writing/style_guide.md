# Writing style guide

The paper reports what the data shows, in plain words, and stops there.

## Voice
- First person plural ("we collected", "we found"). Active voice where it reads naturally.
- Past tense for what we did and found; present tense for what the data and figures show ("Figure 3 shows").
- Short sentences. One claim per sentence. No sales language.
- Words and phrases in `banned_words.txt` are not used. The linter enforces this. Also avoid figurative "fresh".

## Numbers
- Every data number in the text is a macro from `latex/numbers.tex` (generated from `analysis/facts_paper.json`). Never type a data number by hand.
- Literal numbers that are not data (years, "12 tracks", "five hours", event times) must be listed in `allowed_literals.txt` with their source.
- Report effect sizes and 95% confidence intervals. Do not use the word "significant". Write "p = 0.003" or "the difference was small (Cliff's δ = 0.12)".

## Reporting conventions (v2, after review)
| Quantity | Form | Example |
|---|---|---|
| Count with share | n (x.x%) | 1,057 (29.0%) |
| Interval | (95% CI a–b), written out every time | (95% CI 27.5–30.5) |
| Distribution | median (IQR a–b); a CI only when a median is estimated or compared | median 19 (IQR 10–35) |
| Percentages | one decimal in text, tables and figures; always "%", never "per cent" | 87.0% |
| Odds ratios, V, δ, κ, ε² | two decimals | V = 0.08 |
| Test statistics | one decimal, with df | χ²(3) = 14.9 |
| p-values | "p < 0.001" or "p = 0.062" | |
| Time | 24-hour clock with a colon; "ten minutes" in prose, "10 min" in figures | 17:40–17:50 |
| Dates | day month year, British order | 23 September 2026 |
| Thousands | comma separator via siunitx `\num` | 3,649 |
- State the denominator of every share, in the text or in the table or figure header.
- Do not start a sentence with a numeral.
- Terms: *organiser-created repository*, *active repository*, *event window*, *team commit*, *agent trace* (context file, signature, branch), *workflow trace* (pull-request reference), *credential exposure*. One term per concept, in headings, figures and keywords alike.

## Claims we make and how we word them
| Topic | Write | Never write |
|---|---|---|
| Guinness | "organised as an official Guinness World Records attempt for the most participants in an agentic AI hackathon; the result was pending at the time of writing" | "record-breaking", "verified record", "largest in the world" |
| Priority | "to our knowledge, the first repository-level study of …" (only after the literature review supports it) | "first-ever", "pioneering" |
| Vibe coding | "AI-agent-assisted development"; "vibe coding" only when citing the term's origin and related work | calling the event a "vibe-coding contest" |
| Empty repositories | "repositories with no team commits" | "teams that gave up", "no-shows" |
| AI use | "agent configuration files were present in X repositories" | "X teams used AI to write their code" |
| Security | "N repositories contained strings matching secret patterns in their history" | naming repos, showing key fragments, saying keys were "live" |

## Terminology (use consistently)
- *team repository*: a repository the organisers created for one registration.
- *team commit*: any commit except the auto-generated template commit, counted across all branches and deduplicated by SHA.
- *empty repository*: a team repository with zero team commits.
- *event window*: 13:00–18:00 local time (UTC+5) on 23 September 2026.
- *active repository*: a team repository with at least one team commit inside the event window.
- *track*: one of the 12 problem statements; each track had one case.

## Citations
- Cite only works we have found, opened and checked (see `../literature/screening.csv`, column `verified`).
- Prefer peer-reviewed versions; cite arXiv only when no peer-reviewed version exists.
- Grey literature (news, the event site, social media posts) is cited as such, with access dates.

## Figures and tables
- Captions carry the explanation; figures carry no titles.
- Every figure is generated by a script in `figure_code/` from `analysis/` outputs. No manual edits to images.
- One palette (Okabe–Ito), Times-compatible fonts, sizes from `paper_style.py`.
- Colour carries one meaning in every figure: blue is the main series (and Codex), orange is Claude Code, vermilion marks exceptions and exposure (archived before the event, the deadline, key strings still present), grey is context (the organiser batch, strings only in history).
- Short panel titles "(a) ..." are allowed; the caption carries the explanation, the unit and the denominator.

## AI assistance
- The Methods section states which AI tools were used and for what; the Acknowledgments name them (MDPI and arXiv policies). The author checks every number, claim and reference.
